# Krea2 / Jev

Krea2の通常生成・img2img・アップスケールで、層別のSparse Attentionを使えます。VRAM-Canvasには、タイルの細部量に応じて拡散のstep数を配分する別の設定もあります。既定はどちらもOFFです。

## 設定

txt2img / img2imgの **Krea2 · Jev高速化** を開きます。

- **層ごとの高速化**: OFF・固定率・Jev自動・数値ルール・Dense記録を、常に見える選択肢から切り替えます。
- **固定率：画像Attentionの保持率 %**: 1〜100%を1%刻みで指定します。初期値は10%です。固定率のときに調整でき、OFFやJev自動へ切り替えても値を保持します。
- **層のJev再判定頻度**: Jev自動で表示します。初回のみ・指定間隔・毎stepから選択。指定間隔では1〜100stepのスライダーを使います。
- **4K/8Kタイルの高速化（VRAM-Canvas）**: img2imgに表示します。OFF・数値ルール・Jev自動を、層の設定とは独立して切り替えます。OFFでは既存のstep配分を使います。
- **タイル配分のJev再判定頻度**: タイルのJev自動で表示します。初回のみ・拡大段階ごとを選べます。
- **Jev API**: 選んだ設定の頻度を表示します。初回のみでは、固定率だけなら0回、固定率＋Jevタイル配分なら最大1回、両方Jevなら最大2回です。
- **Jev APIキー設定**: 他モデルと共通の保管先を使います。キーは画面へ読み戻しません。Windowsではユーザー領域へDPAPIで暗号化して保存し、Gitや生成メタデータに含めません。

Jevを選んだ機能だけが外部APIを使います。OFF・固定・数値ルールはAPIを呼びません。SDKの準備とキー登録は[共通ガイド](jev-sparse.md)を参照してください。

保持率は画像Attentionで残す計算範囲の割合で、画質の保持率ではありません。小さくすると計算範囲を絞り、100%では通常のAttentionを使います。10%は調整の出発点です。画質と所要時間を見て変更してください。数値が小さいほど必ず高速になるわけではありません。Dense記録は通常のAttentionで比較ログを残すモードです。

### API回数の決め方

各問い合わせで全層、または細部量でまとめたタイル群を一括判定します。層数・タイル数だけの回数にはなりません。**既定の「初回のみ」** では次の上限で、生成・アップスケール1件全体に同じ判定を使います。

| 層ごとの高速化 | タイルの高速化 | Jevへの問い合わせ上限 |
|---|---|---|
| OFF・固定率・数値ルール・Dense記録 | OFF・数値ルール | 0回 |
| Jev自動 | OFF・数値ルール | 1回 |
| OFF・固定率・数値ルール・Dense記録 | Jev自動 | 1回 |
| Jev自動 | Jev自動 | 2回 |

**層の再判定頻度を変更した場合** は、直近の計算結果から統計を取り直します。最初の評価はDenseで統計を集め、次の評価の前に初回の問い合わせを行います。「毎step」は以後の各評価前に、「指定間隔」はその初回判定からN評価ごとに問い合わせます。モデル評価が4回なら初回のみ1回、間隔2なら2回、毎stepなら3回です。終了後の不要な問い合わせはしません。

ここでのstepはサンプラーのモデル評価単位です。Heunなどは画面の1step内で複数回評価するため、設定したSampling Stepsより多くなる場合があります。同じ評価内のCFG条件分岐・メモリ分割では判定を増やしません。アップスケールでは各タイル・各生成パスの最初から統計を取り直すため、モデル評価が4回のタイルが15枚なら、毎stepで最大45回になります。

**タイル配分を「拡大段階ごと」にした場合** は、各段階の細部量を測り直して1回ずつ問い合わせます。2段階なら最大2回です。これは層別の問い合わせに加算されます。対応しないモデル、Sparseの最小トークン数に満たない生成、VRAM-Canvasを使わない場合などは実際の回数が少なくなります。API失敗後は、その生成内で以後の問い合わせを止めます。

初回のみは通信待ちを抑えるための既定値で、理論上の最適回数ではありません。頻度を上げると途中の変化に追従できますが、統計の計算・通信待ち・API利用も増えます。最適な頻度は待ち時間を含む総時間と出力を比較して判断してください。

## 層別Sparse

Krea2生成本体の各層が対象です。標準の28層モデルと、その構造を維持する派生チェックポイントで使用します。Q/K正規化、位置情報、GQA、ゲート、出力投影、MLPは元の処理を使います。文章・参照画像のKVとquery領域は、Comfy-Kitchenの保護範囲で保持します。テキストエンコーダーとTextFusionは対象外です。

最初のモデル評価はDenseで行います。Jevは画像領域のAttention出力ノルムなどの集約統計から、各層の保持率を **1・3・5・10・25・50・100%** から選びます。画像・プロンプト・重みは送信しません。重要度は統計からの推定で、画質の測定値ではありません。有効な回答は信頼度だけを理由に100%へ戻しません。

初回のみではJevの層別判定は生成ジョブ全体で1回までです。Krea2 2-Stage Upscale、VRAM-Canvas、Local Supersample Detail、B5 Whole-Tile Regenerationでは、内部で複数回生成しても判定を再利用します。指定間隔・毎stepでは各生成パスで再判定します。OFFへ戻すと通常のAttentionを使い、成功・失敗・中断の後にジョブの状態を閉じます。

既定では画像部分が4,096トークン未満の領域を通常処理に戻します。小さなタイルはSparseの選択処理が負担になることがあり、Sparseを選ぶだけで高速になるとは限りません。比較時には詳細設定の最小トークン数も揃えてください。マスク付きの未対応経路は通常処理を使います。APIの失敗後も通常処理へ戻し、その理由を記録します。

## タイルのstep配分

Attentionとは独立した機能です。既存の配分は従来の細部量に応じたstep数をそのまま使います。

速度比較と同じ設定を画面で使う場合は、img2imgのScriptを **VRAM-Canvas 4K/8K Highres** にして、品質プロファイルで **Krea2 速度優先 4K** を選びます。1位相・2〜4steps・denoise 0.13・novel detailなしの設定です。従来のプロファイルと既定値も残しています。

速度優先の数値ルールは、細部量が非常に小さい領域の拡散を省き、他の領域へ既存の最小・最大step数を割り当てます。Jevでは最初の拡大段階のタイルを細部量のグループに集約し、グループごとに **0・最小step数・最大step数** を一括選択します。0は拡大済みの入力をそのまま残す意味です。省いたタイルも合成用の重みには参加するため、重なり部分に穴を作りません。

タイル用のAPI呼び出しは初回のみなら1ジョブ1回、拡大段階ごとなら各段階で1回です。初回のみの後続段階では同じ細部量グループの選択を再利用し、未観測グループやAPI失敗時は数値ルールを使います。タイル配分はタイルごとにAPIを呼びません。送信内容はグループごとの枚数・細部量などの集約統計だけです。

## 記録と比較

`outputs/jev-sparse/krea2-*.jsonl` に層別の実行回数・選択値・API待ち時間、`krea2-tiles-*.jsonl` にタイル配分を保存します。VRAM-CanvasのPNGメタデータには各タイルのstep数と拡散を省いたかどうかを記録します。全タイルが0の場合も、拡大画像として完了します。

ローカルAPIを有効にしてNeoを起動し、Krea2・Qwen3-VL 4B・Qwen Image VAEを選んでから実行します。

```powershell
# 1280 / 2048 pxの通常・固定Sparse・Jevを2回ずつ比較。
venv\Scripts\python.exe tools\benchmark_krea2_sparse.py --port 7864 --stage native --output outputs\krea2-native-comparison --allow-cloud

# 層の判定を毎stepに変更。指定間隔なら --decision-cadence interval --decision-interval 2。
venv\Scripts\python.exe tools\benchmark_krea2_sparse.py --port 7864 --stage native --decision-cadence step --output outputs\krea2-each-step --allow-cloud

# 同じ入力で4K全体を比較。1位相・1280pxタイル・2〜4stepsの速度比較設定。
venv\Scripts\python.exe tools\benchmark_krea2_sparse.py --port 7864 --stage 4k --repeats 1 --modes off fixed jev tiles-rules tiles-jev combined fixed-rules fixed-tiles-jev --output outputs\krea2-4k-comparison --allow-cloud
```

比較ツールはAPIの実生成完了までを計り、API失敗による退避をJevの成功結果として扱いません。通常生成の初回はモデル準備用として分離します。4K比較は`--source`で既存の入力画像も指定できます。実行後は一時変更したモデル選択を復元します。

タイル配分を拡大段階ごとに再判定する場合は `--tile-cadence stage` を追加します。頻度を省略すると従来の初回のみです。外部APIのalwayson script引数は既存の5項目の後に `decision_cadence`（`once` / `interval` / `step`）、間隔、`tile_cadence`（`once` / `stage`）を追加できます。従来の5項目だけの呼び出しも使用できます。
