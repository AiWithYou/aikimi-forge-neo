# FLUX 3 Image Klein

FLUX 3 Image Kleinは、文章からの画像生成、最大10枚の参照画像を使う編集、配置ボックスによる構図指定を行う5.6Bモデルです。FLUX.2 Kleinとはモデル構造・テキストエンコーダー・生成方式が異なります。

FLUX 3 Studioからモデルの選択、生成、参照画像の編集、配置指定、結果の保存と中断を行えます。

## モデルと保存形式

| モデル | 既定Steps | CFG | 用途 |
|---|---:|---:|---|
| Klein（蒸留版） | 16 | 1（CFGを使わない） | 通常の生成・編集 |
| Klein Base | 50 | 3.5 | 通常版での生成・編集、比較 |

公式Comfy配布のファイル名では、`_sd_`を含むものが蒸留版、含まないものがBaseです。実際の読み込み時にもモデル構造を照合します。

RTX 3090などのAmpere GPUでは、公式INT8 ConvRotを本体とテキストエンコーダーの既定にします。BF16、Blackwell向けNVFP4も選択できます。公式のFP8 rowwise配布とGGUFは本Studioの導入対象に含めません。対応しないGPUで選んだ形式を、別の形式へ黙って変更しません。

NVFP4は生成本体の形式で、テキストエンコーダーにはINT8を使います。VAEはどの形式でもFP32で読み込みます。

モデルは専用の管理フォルダーへ取得します。Iris・H3・Mingなどの既存ランタイムや重みを更新・削除しません。取得は固定revision・ファイルサイズ・SHA-256で検証し、中断後に再開できます。モデルをGitHubの配布物へ含めません。

起動後の最初の準備確認や生成では、重みの整合性検証に時間が掛かる場合があります。

## 生成と編集

文章のみ、参照画像による編集、配置指定を同じStudioから実行します。画像は入力順を維持し、最大10枚です。入力画像のEXIF方向を反映します。

参照画像1枚では縦横比を保って最大4メガピクセル・長辺4096以内へ調整し、16pxの格子へ中央パディングします。出力サイズを指定しないときは参照画像のサイズに合わせ、追加した余白を出力から取り除きます。複数枚では各参照を最大1メガピクセルへ縮小し、16pxの格子へ中央クロップします。元の画像は変更しません。

文章からの生成の既定は1024×1024です。指定できるサイズは各辺64〜4096、16px単位です。大きな出力や多数の参照に必要なVRAMと処理時間は増加します。使用しないモデルはGPUから退避し、大きな参照画像の変換や高解像度の復号は空きメモリに応じた分割処理で消費を抑えます。分割の境界付近は非分割と画素が完全に一致するとは限りません。失敗時には出力を成功扱いにしません。

蒸留版は各ステップの到達時刻を入力するflow-map方式を使います。Baseは空の文章を使う無条件側と指定文章側のEuler＋CFGを使います。FLUX.2用のSteps・スケジュールは流用しません。

## LoRA

FLUX 3用のLoRAを`models/Flux-3-Klein/loras/`へ置き、Studioの「LoRA」の「更新」で一覧を読み直します。起動時は「なし」から選択します。LoRAを選び、強度を調整して生成します。「なし」または強度0では適用しません。Base用と明記されたLoRAを選ぶと、モデルもKlein Baseへ切り替わります。

対応する形式は、FLUX 3本体の`diffusion_model.*`を対象とする通常のsafetensors LoRAです。テキストエンコーダーは変更しません。down/upまたはA/Bの同じ形式の組に対応し、一つの組の中で両形式を混在させる指定は受け付けません。rank・対象レイヤー・形状・有限値を確認し、不一致や未対応のキーを黙って無視しません。生成受付後にファイルが上書きされた場合も生成を止めます。

各生成で選択したLoRAだけを適用し、LoRAの切り替え・解除・強度変更を次の生成へ反映します。名前、SHA-256、ファイルサイズ、強度、適用対象数をPNGと生成条件JSONに記録し、履歴でも保持します。LoRAの重み自体や保存先の絶対パスは記録しません。

## 配置ボックス

Studioの「配置」を開き、枠の中をドラッグして矩形を描きます。追加された要素の説明を入力し、不要な要素は「削除」で取り除きます。「描いた枠をクリア」は通常の矩形だけを消し、高度な編集で指定した移動・削除の情報は残します。枠の縦横比は選択した出力サイズに合わせます。

「高度な編集・座標」でJSONを直接編集すると、描画と要素の説明にも反映されます。参照画像の移動元・移動先や`null`による削除も、このJSON欄から指定できます。描画や説明の変更でも既存の編集指定は保持します。

各要素に識別子と説明を付け、座標は左上を原点とした`[上, 左, 下, 右]`の0〜1で指定します。プロンプトへ渡す際に公式形式の0〜1000へ変換します。

```json
[
  {"id": "obj_1", "desc": "赤い気球", "bbox": [0.08, 0.10, 0.45, 0.42]},
  {"id": "obj_2", "desc": "崖の上の灯台", "bbox": [0.30, 0.60, 0.95, 0.90]}
]
```

編集では`from: "ref_image_0"`のように0番から参照画像を指定し、`src_bbox`と`tgt_bbox`で移動元と移動先を指定できます。`from: "target"`は新しい要素を指定します。移動先を`null`にする削除も公式形式に従って処理します。

ボックスは要素の位置と大きさを誘導します。ピクセル単位のマスクではなく、ボックス外を完全に保持する保証はありません。

## プロンプト補完（PUP）

PUPは任意の追加機能で、**既定はOFF、通常の導入では取得しません**。公式のQwen3.5-9Bベースの補完モデル（INT8で約9.8GB）を別途導入すると、短い指示を完成画像の詳しい説明へ展開できます。OFFでは入力した文章をそのまま使います。画像編集では参照画像も補完モデルへ渡します。配置ボックスを指定した場合、ユーザーが指定した識別子・参照先・座標・`null`を補完後にも維持します。

導入後はStudioの「プロンプト補完（PUP）」をチェックしてから生成します。チェックを外すと補完せずに生成します。補完前後の文章は保存条件JSONに残り、「履歴」から確認できます。

PUP・テキストエンコーダー・生成本体は順番に実行し、使用しないモデルをGPUから退避します。PUPをOFFにした生成で補完モデルを読み込みません。補完後の文章は確認・保存できます。

## 保存と中断

結果はPNGと生成条件のJSONで保存します。入力文章・補完後の文章・モデルの種類とrevision・保存形式・LoRA・Steps・CFG・seed・出力サイズ・配置情報・参照画像の順序を記録します。PNG内にも生成条件を保存します。

中断は専用ランタイムへ伝え、GPU処理の停止を確認してから次のモデルへGPUを返します。生成途中の画像を完成画像として履歴へ追加しません。

## 履歴

上部の「履歴」を開くと、`outputs/flux3-klein`に保存した最新50件までの完成結果を選べます。過去に生成した画像も自動で見つけ、アプリの再起動後も一覧に残ります。「更新」で一覧を読み直せます。

結果を選ぶと履歴の画像と生成に使用した文章を表示し、PNGと条件JSONを取得できます。元のプロンプト、seed、配置情報などの詳細は条件JSONで確認できます。履歴にはこの使い方ガイドへのリンクもあります。

中断・失敗・未完了・破損した結果や、保存先の外へつながるファイルは表示しません。選択時にも保存記録とPNG内の条件、保存した参照画像のハッシュと順序を照合します。履歴を開いても生成やモデルの読み込みは行いません。

導入先と履歴の保存先は、Windowsの8.3短名にも対応します。symlink・junctionを経由する保存先やファイル、管理範囲外への参照は受け付けません。

## 確認範囲

RTX 3090で公式INT8・PUP OFFの蒸留版とBaseを確認しています。1024×1024生成、参照画像1枚の編集、10枚の参照入力、配置ボックス指定、3840×2160生成、途中中断後の再生成を実行しました。参照の順序と生成条件を保存し、完成PNGと照合します。

同じ環境のKlein Baseでrank32のnative LoRAを適用し、1024×1024・50 Steps・CFG 3.5で生成を確認しました。同じ文章・seedのLoRAなしと比較し、強度0ではLoRAなしと画素が完全一致します。LoRAの条件はPNG・JSON・履歴でも照合します。LoRAを使うBF16・NVFP4と参照画像編集の実生成は未確認です。

同じ環境で公式INT8のPUPを追加し、短文補完からの生成と、参照画像1枚・配置ボックスを使う編集を確認しました。通常画面でPUPをONにし、補完前後の文章・参照・座標の保持、PNGと条件JSONのダウンロード、履歴からの再表示とガイドへの移動まで確認しています。

通常のForge Neo画面でも、配置の描画から生成・画像表示・PNGと条件JSONの保存まで確認しています。

BF16の実生成とNVFP4のBlackwell実機動作は未確認です。これらの形式をINT8と同じ検証済み範囲として扱いません。PUPの実機確認条件は[この版のRelease](https://github.com/AiWithYou/aikimi-forge-neo/releases/tag/v4.6.0)の「確認範囲」を参照してください。

## 導入とライセンス

```powershell
.\aikimi-flux3-klein-setup.bat
# Baseを追加する場合
.\aikimi-flux3-klein-setup.bat --model base
# 必要な場合だけPUPを追加する
.\aikimi-flux3-klein-setup.bat --with-pup
# 重みを取得せず、専用実行環境だけを準備する場合
.\aikimi-flux3-klein-setup.bat --runtime-only
```

BF16を導入する場合は`--precision bf16`、NVFP4は`--precision nvfp4`を追加します。`--dry-run`は取得予定だけを表示し、ファイルや実行環境を変更しません。

通常の導入にPUPは含まれません。`--with-pup`で追加しない限り、補完モデルの取得・読み込みは行いません。

重みの取得にはHugging Faceでのアクセス承認が必要です。認証トークンはURL・生成条件・ログ・公開物へ保存しません。

APIは通常のAPI認証設定に従います。`POST /sdapi/v1/flux3/jobs`へ生成条件を送信し、返された`id`を`GET /sdapi/v1/flux3/jobs/{id}`で確認します。参照画像は`images`配列へbase64形式の画像として送り、URLやローカルパスは送りません。中断は`POST /sdapi/v1/flux3/jobs/{id}/cancel`です。完了時にはPNGのbase64、生成条件、参照画像のハッシュを返します。

LoRAは`lora: "example.safetensors"`のように専用フォルダー内の相対名で指定し、`lora_strength`は0〜2の有限の数値を指定します。未指定はLoRAなし、強度の既定は1です。URL、絶対パス、管理フォルダー外への参照は受け付けません。
