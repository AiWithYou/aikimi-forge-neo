# Forge Neo更新の確認記録

## 2026年9月22日

`upstream/neo` の `c21fa928cc08f2662fbcaedf3389858e7cf4a16f` までを確認し、[ControlLLLiteとMultiDiffusionの併用対応（b469e221）](https://github.com/Haoming02/sd-webui-forge-classic/commit/b469e2214f182b7df07a6ba8fdb82824c62c007f)を選択的に取り込みました。対象3ファイルに後続の関連修正はありませんでした。一括マージと依存関係の変更は行っていません。

SDXL・Animaの条件画像をタイルと同じ位置・バッチ順序で切り出し、MultiDiffusionとMixture of Diffusersの両方に適用します。上流に加えて、タイル処理を抜ける際は例外・中断時も元の条件へ戻し、失敗時のタイルキャッシュを破棄する処理を追加しました。Animaの元の条件埋め込みは再計算せず復元し、条件画像の再設定とdevice・dtype変更ではキャッシュを無効化します。ControlLLLiteの開始・終了ステップがタイル数によって進まないようにもしています。

生成全体の既存 `on_process_cleanup` にControlNetの未解除モデルを接続し、正常なバッチ後は二重解除を避け、例外時は適用と逆順に解除します。既存の `ControlLLLiteAdvanced` 互換分岐は維持しました。

検証は `tools/tests/test_controllllite_tiling.py` の11件と既存の生成終了・上流回帰テストを合わせたCPUテスト32件が成功しました。通常→タイル→通常、複数画像のタイルバッチ、開始・終了ステップ、条件変更、中断・例外後の再生成、Animaの5次元入力と埋め込み再利用を確認しています。変更対象4ファイルのRuff指摘は変更前と同じ22件で増加はなく、新規テストのRuff検査と差分の空白検査も成功しました。GPU実生成による画質・速度比較は未実施です。

## 2026年9月21日

`neo` の `41359cd4` までを比較し、`3baffa8b` の量子化メタデータと重みprefixの不一致への対処を取り込みました。層名の候補が複数ある場合を拒否する検査と回帰テストも追加しています。RoPE変更はRTX 3090で比較しましたが、今回の条件では速度改善を確認できなかったため見送りました。採否の一覧と測定条件は [量子化監査記録](quantization-audit-2026-09-21.md) にまとめています。

## 2026年9月12日

2026年9月12日、Forge Neoの`neo`ブランチを取得し、[76586f6a](https://github.com/Haoming02/sd-webui-forge-classic/commit/76586f6a)までの変更を現在のAikimi実装と比較しました。一括同期の基準は`0d0cb72951b059c8ea17861ba86db8d0f6098c28`のままです。

## v1.0.0での判断

| 更新 | 判断と理由 |
|---|---|
| GPU起動時の`no kernel image`の案内（`370e4df1`） | 採用。単なるGPU検出失敗と区別し、PyTorchの版を見直す案内を表示します。依存関係の自動変更は行いません。 |
| OOM例外判定（`d2c29a6b`） | 反映済み。例外クラスがない場合に、すべての例外をOOMと扱わない処理を維持します。 |
| Anima LoRAのブロック番号の厳密な解析（`1efa302b`） | 同じ問題への対処が実装済み。既存の変換処理は28・40・52層、複数のキー形式を扱い、元の層数が不明なLoRAを推測で変換しません。 |
| 生成ショートカットの監視解除・不要なキー入力処理の省略（`4f5f2264`、`84c491cb`） | 同じ目的の処理が実装済み。専用Studioや生成ボタンがないタブにも対応するAikimi側の処理を維持します。 |
| PyTorch・Gradioなどの依存関係変更 | 見送り。AikimiはPyTorch 2.11.0とGradio 6.17.3を基準に検証しており、Forge側の構成とは異なります。 |
| pyNVMLによるVRAM計測（`1d413a56`） | 見送り。デバイス0固定の計測と空きVRAMからの追加減算について、複数GPU・既存計測との整合を検証してから判断します。 |
| LoRAのステップ別制御、SolAttn、Attention上書き | 見送り。生成結果や量子化LoRAの適用に関わるため、対応モデルでの比較を伴う別の更新として検討します。 |
| プロンプトの前後空白を残す設定・メタデータ編集UI | 見送り。今回の公開準備では、既存の操作と保存形式を維持します。 |

採用済みと記載した項目はソースの照合結果です。今回、新しいモデルによるGPU生成比較は行っていません。
