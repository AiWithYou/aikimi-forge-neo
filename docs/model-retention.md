# モデル保持と連続生成

画面上部の **GPU・モデル保持** から設定します。設定は全画面共通で、再起動後も保存されます。

| 設定 | 生成後の動作 |
|---|---|
| 自動（既定） | 同じエンジンの生成では再利用し、最後の処理から5分経つと待機モデルを解放 |
| 連続生成を優先 | 待機中も保持。別の機能がGPUを使うとき、または「今すぐモデルを解放」で解放 |
| 毎回解放 | 1回の生成処理が終わるたびにモデルを解放 |

実行中に設定を変えた場合は、その生成が終了してから適用します。「今すぐモデルを解放」は実行中の生成を停止しません。生成の停止は各Studioの停止ボタンを使ってください。

## 機能ごとの動作

- **Forge・Krea2・Anima**: Forgeの既存のモデル再利用とメモリ管理を使います。
- **SenseNova**: 専用Pythonと読み込み済みの実行環境を再利用します。モデル・LoRA・VRAMモードなどが変わると読み込み直します。
- **YuE2公式Python**: 同じ設定ならパイプラインと専用Pythonを再利用します。一括指定した複数候補の生成中も再利用します。
- **H3 Studio・H3 Image**: ComfyUIのモデル保持を利用します。解放時はNeoが起動した専用ComfyUIを終了し、GPU使用プロセスの終了を確認します。次にH3を使うときは自動起動します。
- **背景除去**: 選択中のモデルを再利用します。Forgeの画像生成モデルがGPUを使うときは背景除去モデルを解放します。

YuE2のCPU退避、SenseNovaの低VRAMモードなど、生成工程ごとのメモリ節約設定は引き続き有効です。保持するモデルの一部がCPUメモリにある場合もあります。全モデルを同時にVRAMへ載せる設定ではありません。

audio.cppは現在のCLIが生成ごとに終了するため、GGUFモデルを生成ボタンの操作間で保持する対象には含みません。CPUだけで動く仕上げ処理にもこの設定は適用しません。

## GPUを共有するとき

同時実行を防ぐGPU使用権は生成終了後に返し、待機モデルの保持とは分離しています。別のエンジンへ切り替える際は、そのエンジンの読み込み前に待機モデルを解放します。停止や退避を確認できない場合は次の生成を開始せず、エラーを表示します。

外部で起動したComfyUIは自動終了しません。H3から他の機能へ切り替える際に解放が必要な場合は、外部ComfyUIの終了を案内します。また、この設定は他アプリが直接使っているGPUメモリを管理しません。

実機での連続生成と解放の確認結果は[検証記録](model-retention-validation.md)にまとめています。
