# DetailWeave 4K：二つの分割候補から細部を選ぶ高精細拡大

**DetailWeave 4K: Input-Preserving Local Selection of Two Tiled Candidates**

**あいきみ**

## 要旨

大画像処理では、画像と潜在画像の変換を小領域へ分ける分割VAEと、一つの格子で画像から画像への局所生成を行う分割拡大が広く使われる。前者は変換の省メモリー化であり、新しい細部を生成しない。後者はGPU作業領域を固定できる一方、格子位置によって細線が変わる。本稿は、半格子ずらした二つの完成候補から候補A、候補B、入力維持を局所選択するDetailWeave 4Kを示す。Lanczos補間、単一格子分割、提案法を2897×4096で比較した。本手法は特定の画像モデルへ依存しない。

**キーワード：** 4Kアップスケール、分割VAE、分割生成、局所選択、入力維持

## 1. はじめに

画像を大きくする最も単純な方法は、周囲の画素から新しい画素を計算する補間である。Lanczos補間は構図と色を保つが、元画像にない髪の細線や布目は生成しない。生成モデルを使えば細部を描き足せる一方、大画像を一度に扱うには多くのメモリーが必要になる。

現在はVAEの変換を重なり付き領域へ分ける分割VAEが一般化している。しかし、これは入口と出口の変換を省メモリー化する機構であり、拡散生成自体を分けない。局所生成まで分ける単一格子法は大画像を扱えるが、領域位置が変わると同じ毛束や文字状の線が数ピクセルずれる。

## 2. 比較する三つの拡大法

### 2.1 Lanczos補間

入力画素だけから拡大する。生成による形の変化はないが、新しい意味的細部も増えない。本稿では、入力由来の形を確認する基準として用いる。

### 2.2 分割VAEと単一格子分割

潜在拡散モデルは、VAEを使って画像と潜在画像を相互変換する。分割VAEは、この符号化と復号だけを重なり付き領域へ分け、境界を重み付き平均する。指示文による生成や細部選択は行わない。実測比較には、画像から画像への局所生成と候補整形を共有し、一つの格子だけを採用する単一格子版を用いる。

### 2.3 DetailWeave 4K

位置をずらした二配置を別々に最後まで処理し、同じ寸法の完成候補AとBを作る。その後、場所ごとにA、B、入力維持を選ぶ。単一格子法と同じ省メモリー性を保ちながら、格子位置への依存と不適切な描き足しを抑える。今回用いた画像モデルは実験条件にすぎず、選択・合成アルゴリズムはモデル固有ではない。

## 3. 提案手法

### 3.1 二つの格子配置

一領域では1280×1280画素をモデルへ入力し、周囲160画素を文脈として使う。中央960×960画素を候補へ戻す。中央部は880画素ずつ先へ進むため、隣同士は80画素重なる。

出力2897×4096に対し、配置Aは4列×5行の20領域、配置Bは格子を縦横へ440画素ずらした4列×6行の24領域である。AだけでもBだけでも画像全体を完成させる。左右分割や市松分担ではない。端では画像外へ端画素を延長し、モデル入力を常に1280×1280へ保つ。

### 3.2 配置ごとの独立再構成

入力補間画像に対する配置 `g`、領域 `t` の変化を `Δ(g,t)`、窓重みを `w(g,t)` とする。配置ごとに重み付き和 `Dg`、重み和 `Wg`、変化エネルギー `Eg` を独立に蓄積する。

```text
Dg = Σt w(g,t) Δ(g,t)
Wg = Σt w(g,t)
Eg = Σt w(g,t) mean(Δ(g,t)²)
Rg = Dg / Wg
```

同じ配置内で重なる領域のばらつきから安定度 `Cg` を求める。ここではAとBをこの段階で混ぜない。

### 3.3 低周波を入力へ寄せる

候補差分 `Rg` を標準偏差12画素相当の低周波 `RgL` と高周波 `RgH` に分ける。

```text
RgL = G12(Rg)
RgH = Rg - RgL
R'g = RgH + ηY RgL,Y + ηC RgL,C
```

高周波は保ち、低周波は輝度0.32、色差0.18へ弱める。入力輝度0.85以上では輝度係数をさらに半減する。これにより、髪、刺繍、木目などを残しつつ、服全体の大きな陰影、白髪の発光感、肌色の変化を抑える。

### 3.4 細部量と入力忠実度

変化の大きさだけを品質とはみなさない。高周波量 `Hg` に配置内安定度 `Cg` と入力忠実度 `Fg` を掛ける。

```text
Qg = Hg (0.25 + 0.75 Cg) Fg
Fg = exp(-1.25 d_edge - 1.00 d_low - 0.75 d_chroma)
```

`d_edge` は入力と候補の輪郭方向の不一致、`d_low` は低周波輝度差、`d_chroma` は低周波色差である。架空の文字、増えた毛束、布の大きな塗り、過剰な反射は忠実度を下げる。

### 3.5 A、B、入力維持の三値選択

入力輝度を案内画像として評価画像を半径16で整理し、忠実度を半径8で整理する。AとBの相対得点を次式で求める。

```text
S = (QB - QA) / (QA + QB + ε)
```

- `S > 0.03` ならB
- `S < -0.03` ならA
- `|S| ≤ 0.03` なら未確定
- 両候補の忠実度が0.42未満なら入力維持

未確定部には周囲の確かな選択を伝え、3000画素未満のA/B島と穴を整理する。二候補が不適切なら入力補間へ戻す。二候補が近い場合だけ±1画素で位置を合わせて弱く融合し、整理後の境界だけを5画素で接続する。単純な広いぼかしではなく、入力画像の輪郭へ選択境界を寄せる。

### 3.6 補助候補を弱く使う

選択候補を `R*`、位置合わせした補助候補を `R-`、候補の近さを `a` とすると、補助差分は次式である。

```text
Rsup = R* + 0.10 a² (R- - R*)
Rout = (0.90 + 0.10 a) Rsup
```

局所構造類似度が0.90以上で輪郭方向も揃う場合だけ補助する。`a` を二乗するため、かなり近い候補に限って最大10%が働く。位置がずれた毛束や文字状の線は混ぜず、選択候補を鮮明なまま使う。

## 4. 事例検証

### 4.1 条件

同じ入力を2897×4096へ拡大した。単一格子像はDetailWeaveの配置Aを全面採用したもので、二方式は同じ局所生成を共有する。生成には**独自に調整したKrea2 Turboモデル**、同じ指示文、各領域6回（Exact Steps）、変化強度0.16を用いた。これは実験条件であり、DetailWeaveの選択式には関与しない。

| 方法 | 処理 |
|---|---|
| Lanczos | 補間のみ |
| 単一格子分割 | 配置Aの20領域を全面採用 |
| DetailWeave | A 20領域 + B 24領域 |
| 生成条件 | 各領域6回（Exact Steps）、変化強度0.16 |

### 4.2 候補選択の可視化

![Lanczos、候補A、候補B、DetailWeaveの全体比較と400%拡大クロップ](../output/detailweave_paper_image_cropped_20260722/paper_assets/phaseweave_paper_comparison.png)

図の上段はLanczos、候補A（単一格子）、候補B、DetailWeaveの全体像である。下段は同一座標を400%表示した。左から単一格子A、候補B、DetailWeave、`|A - DetailWeave|`の差分強調、最終像へ選択マスクを重ねた図である。矢印は候補間で線の位置や形が変わる箇所を示す。青い髪では主にB、本の頁では主にAが採用されている。マスクは橙がA、青がB、灰が入力維持、紫が近い二候補の弱い融合を表す。

### 4.3 評価方法

Lanczos像を正解ではなく入力維持の基準とする。細かな明暗変化は、輝度から2画素相当の平滑成分を引いた絶対値で測り、Lanczosを1とした。低周波明暗ずれは12画素相当の平滑像との差、RGB平均差は0から255の画素値差である。輝度SSIMは構造の近さを表し、1に近いほどLanczos像へ近い。

境界ジャンプ比 `J` は、A/B両配置の計画境界における生成残差の隣接画素ジャンプの95百分位を、画像全体の同じ値で割る。

```text
J = P95(|ΔR| at planned boundaries) / P95(|ΔR| over the whole image)
```

`J = 1` は計画境界が画像全体と同程度、`J > 1` は変化が境界へ集中していることを表す。`J < 1` では、小さいほど境界上の変化が画像全体に対して弱い。この指標も細部の正しさを直接判定しないため、同一座標の拡大比較を併用する。

### 4.4 結果

| 評価量 | Lanczos | 単一格子 | DetailWeave |
|---|---:|---:|---:|
| 細かな明暗変化 | 1.000 | 1.040 | 1.014 |
| 低周波明暗ずれ | 0.000 | 0.336 | 0.338 |
| 輝度SSIM | 1.000 | 0.749 | 0.760 |
| RGB平均差 | 0.000 | 7.724 | 7.508 |
| 境界ジャンプ比 J（低いほど境界変化が弱い） | - | 0.990 | 0.978 |

三方式とも2897×4096を出力した。単一格子像と提案法は一回の同じ領域生成から得ており、差は二配置の完成後に行う選択、拒否、境界接続にある。

単一格子の細かな明暗変化は1.040倍、提案法は1.014倍であった。提案法は変化量を最大化せず、輝度SSIMを0.749から0.760、RGB平均差を7.724から7.508へ改善した。境界ジャンプ比は0.990から0.978へわずかに低下し、計画境界への変化集中は増えなかった。

400%拡大では、候補AとBで毛束の線位置や本の文字状模様が異なる。最終像は、青い髪の例ではB、本の頁の例ではAを主に採用している。したがって、結果は単一格子Aを一様に採用したものでも、AとBを一様に平均したものでもない。

提案法はAを49.80%、Bを49.84%選び、入力維持は0.020%、近い二候補の弱い融合は0.342%であった。境界接続帯は12.37%、平均補助率は0.0094であり、大部分では一候補を鮮明なまま使った。

## 5. 標準的な分割処理との違い

### 5.1 分割VAEは入口と出口を分ける

VAEは画像を生成モデルが扱う潜在画像へ変換し、最後に画像へ戻す。分割VAEはこの計算を小領域へ分けるため、VAEのGPU作業量を抑えられる。ただし一般的な実装は、全体潜在画像、全体RGB出力、タイル結果の加算バッファ、重なりを正規化する重みバッファをCPUメモリーに保持する。新しい細部を生成せず、ノイズ除去や指示文にも手を加えない。

DetailWeaveが分けるのは画像から画像への局所生成の全経路である。二候補を生成して忠実度を評価し、A、Bを拒否して入力維持も選べる。分割VAEの代替ではなく、その上で動く生成・選択層であり、各領域には通常VAEと分割VAEのどちらも使える。

MultiDiffusionはさらに別の方式であり、ノイズ除去の各段階を分け、各予測を一つの共有潜在画像へ戻す。分割VAE、単一格子の局所img2img、DetailWeaveは、分割している処理段階がそれぞれ異なる。

### 5.2 単一格子に加えるもの

単一格子分割とDetailWeaveは、どちらもモデルが一度に見る領域を固定し、全体結果をCPUメモリーまたはディスクへ蓄積できる。このため両方式ともGPUメモリー使用量を出力解像度から切り離せる。

違いは選択肢である。単一格子は一つの完成像を採用する。DetailWeaveは格子を半分ずらした二候補を完成後まで保ち、局所的にA、B、入力維持を選ぶ。省メモリー性を保ったまま、格子位置に依存する細線と不適切な描き足しを抑える。

### 5.3 用途による使い分け

| 用途・重視する点 | 向いている方式 |
|---|---|
| VAE変換だけを省メモリー化 | 分割VAE |
| 計算量を抑えた局所生成 | 単一格子 |
| 元画像に忠実な高精細拡大 | DetailWeave |
| 髪や文字など細線を守る | DetailWeave |
| 不適切な生成を入力へ戻す | DetailWeave |
| GPUメモリーと出力解像度を分離 | 単一格子・DetailWeave |
| 局所生成部を32K・64Kへ段階的に拡大 | 単一格子・DetailWeave |

出力を2倍にすると領域数、処理時間、一時保存量はおおむね4倍になるが、一領域のGPU作業量は変わらない。この局所生成部は32K・64Kにも同じ処理を反復できる。最終復号と画像保存まで総メモリーを一定にする場合は、全体RGB画像を一度に保持しない帯状の逐次復号・逐次保存を組み合わせる。

## 6. 結論

DetailWeaveは分割VAEを置き換えず、単一格子分割の省メモリー性へ二候補と入力維持の選択を加える。実測では単一格子より入力構造への近さを改善し、計画境界への変化集中を増やさなかった。元画像に忠実な超高精細拡大に適した構成である。
