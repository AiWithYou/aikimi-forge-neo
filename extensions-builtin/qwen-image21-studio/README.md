# Qwen Image 2.1

Qwenの公式Diffusersパイプラインを専用環境で実行する画像生成・編集タブです。Neo本体の依存関係を変更せず、既存のQwen-Imageモデルと併用できます。

## 導入と使い方

1. Neoを終了し、ルートの`aikimi-qwen-image21-setup.bat`を実行します。Python 3.13、Git、NVIDIA GPUが必要です。
2. 公式モデル一式約33GBと専用環境を準備します。環境の容量も含めて余裕を確保してください。同じBATを再実行すると取得済みファイルを再利用し、モデルのサイズとSHA-256を検証します。
3. 普段の`aikimi-launch.bat`で起動し、上部の**Qwen Image 2.1**を開きます。
4. プロンプトを入力し、最初は**INT8・CPU退避・1024×1024・40 steps**で生成します。Seedが`-1`なら毎回ランダムです。実際に使ったSeedは結果と一緒に保存します。

参照なしで新規生成、参照を追加すると画像編集になります。最大10枚を順番に指定できます。画像内の人物や物を指すときは「1枚目」「2枚目」のようにプロンプトに書いてください。透過背景を有効にすると公式の透過指示をプロンプトへ加え、生成したアルファチャンネルをPNGへ保存します。背景が確実に透明になることを保証する後処理ではありません。

結果は画面から保存し、そのまま次の編集の参照にも使えます。保存先は`outputs/qwen-image-2.1/`です。各生成の`request.json`、`result.json`、`output.png`、`worker.log`に設定・画像・実行記録が残ります。停止はその画面で開始したジョブにだけ作用します。ブラウザーを閉じてもジョブは継続し、実プロセスの停止確認が終わるまでGPU使用権を保持します。

## 囲んだ場所を編集する

1. **編集元・描き込み**へ参照画像を追加します。1枚なら描画欄が自動で開きます。複数枚の場合は対象を選び、**選択画像を開く・囲む**を押します。
2. i2iと共通のForge Canvasで対象を囲みます。ペンの色・太さを変更でき、**Fで拡大・縮小、Shiftを押しながら描いて消去、Ctrl+Z/Ctrl+YでUndo/Redo**ができます。ツールバーからも操作できます。
3. 画像の横にある編集指示へ、例えば「赤い囲みの切符と台座を消して、机の木目になじませて」と入力し、**生成・編集**を押します。精度のINT8/BF16は常に表示します。
4. **この画像を続けて編集**を押すと、生成結果だけを新しい編集元にして描画欄を開きます。複数参照に加えたい場合は**参照画像に追加**を使います。

囲みは描画欄を開いている間、次の生成に使います。**囲みを使わず閉じる**で解除できます。参照を並べ替えても描画対象は元の画像を追い、対象を削除すると描画欄も解除します。元画像、描画レイヤー、囲み付き入力は別々に保存され、元画像を上書きしません。透過画像は描画時だけ白背景でプレビューし、モデルに渡す入力では元のアルファを保持してペンを重ねます。

完了すると**生成結果**へ切り替わります。次の生成中も前の画像を表示し、編集元との切り替えやPNG・生成条件の保存ができます。

結果からの編集、参照の追加・並べ替え・削除の後も、アップロードとクリップボード貼り付けを続けられます。

これは[公式のLocal Editing](https://github.com/QwenLM/Qwen-Image-2.1#local-editing)に沿った、**色付きの注釈をモデルへ見せる編集**です。囲み線を消し、対象外をできるだけ保つ指示を自動で加えます。**範囲外のピクセルを完全に固定するマスク編集ではありません。** 囲み線の消去や編集範囲の遵守は生成結果を確認してください。入力の追加で参照枚数は増えないため、最大10枚のまま使えます。INT8/BF16の両設定で同じ操作です。

2026年9月21日、RTX 3090で1024×1280・40 steps・INT8・CPU退避の囲み編集を2回実行しました。リボンの色変更は囲み線が消えましたが、保持を指定した襟も変色しました。続く小物の削除では、囲んだ切符と台座が消え、机の木目で補完されました。生成処理は約105秒・110秒（初回モデル読み込み約871秒は別）です。画面のUndo/Redo、並べ替え後の参照追跡、削除時の解除、透過PNGの保持、結果からの編集は別途操作と回帰テストで確認しています。

描画欄の更新後も、実WebUIで切符と台座を囲んで削除しました。同じ入力・Seed 92113で2回実行し、生成処理は約96秒と約92秒、初回モデル読み込みは約858秒でした。2回目は読み込み済みモデルを再利用し、2枚のRGBA全ピクセルが一致しています。元画像のピクセルも保持されています。新しい編集元へ切り替えた後、Undoで以前の囲みが戻る問題も修正しています。

## マスク範囲外を固定する

**マスク範囲外を元画像に固定**は初期値OFFです。ONにして変更する部分を専用のマスク欄で塗るか、編集元と同じサイズのマスク画像をアップロードします。アップロードは白が編集、黒が保持で、透明な画素も保持します。囲みの目印と編集マスクは別々に保存され、囲み線が自動でマスクになることはありません。

出力サイズを**編集元と同じサイズ**にするか、編集元と完全に一致するサイズを選択してください。生成条件の制限（32の倍数・約430万画素以内）も適用します。元画像・マスク・生成画像のサイズが違う場合はリサイズせず拒否します。境界のぼかしはマスクの内側だけに適用し、マスク外とマスク内の穴は透明度や透明画素のRGBを含めて元画像のまま保持します。

生成後に編集部分だけを元画像へ合成する機能です。モデルに渡す囲みの目印は併用できます。結果の**範囲外固定／生成そのまま**で表示を切り替え、選択中の画像を次の編集や参照へ使えます。`output-preserved.png`と元の生成結果`output.png`を両方保存し、PNG・生成条件の保存欄から取得できます。編集元、`edit-mask.png`、境界設定もジョブ内に保存します。

## プロンプト書き換えのON/OFF

プロンプト欄の下にある**プロンプトを書き換える（4bit）**で切り替えます。初期値はOFFです。ONでは[公式のQwen-Image-2.1-PE-T2I](https://huggingface.co/Qwen/Qwen-Image-2.1-PE-T2I)を使い、日本語などの短い依頼を詳しい英語の画像説明へ展開してから生成します。画像内に入れる日本語の文字列は、公式の指示文に従って元の言語で保持するよう指定します。

この文章用スイッチは参照画像がない新規生成で実行します。参照画像・囲みを使う編集ではONでも自動で省略します。画像編集の指示補助は、次の独立したスイッチで切り替えます。出力サイズは画面の選択を維持し、その比率をモデルにも伝えます。透過背景の指示は書き換え後に加えます。完成後の**使用したプロンプト**と、保存される`result.json` / `metadata.json`で、実際に画像生成へ渡した文章を確認できます。

追加導入は次のコマンドです。既存のQwen専用環境が正常なら、その依存関係と画像モデルを再導入せず、書き換えモデルだけを追加します。

```bat
aikimi-qwen-image21-setup.bat --prompt-rewriter-only
```

画像モデルと一緒に準備する場合は`--with-prompt-rewriter`、書き換えモデルのSHA-256を再検証する場合は`--prompt-rewriter-only --verify`を付けます。導入中はQwenの待機モデルを解放してください。

量子化は**4bit NF4＋二重量子化**で、文章生成に不要なVision部を外し、大きな出力ヘッドも4bit化します。埋め込みや正規化などは浮動小数点であり、全パラメーターを一律4bitにする設定ではありません。主な行列演算はBF16です。固定した公式重みからローカルで量子化し、`models/Qwen-Image-2.1/prompt-rewriter-nf4/`に再利用できる形式で保存します。導入時だけ約19GBの元重みを取得し、変換とファイル検証が成功した後、その導入専用の一時重みを削除します。既存のHubキャッシュには触れません。

実行時のダウンロードや外部API送信はありません。OFFなら書き換えモデルを読み込みません。ONでも書き換えが終わると補助モデルを解放してから画像生成へ進みます。読み込み済みの画像モデルは必要に応じてCPUへ退避させ、再利用を維持します。書き換えも通常の生成と同じGPU所有権と停止処理で管理します。

待ち時間を抑えるため思考モードをOFFにし、出力上限を4096トークンにしています。量子化前や公式の思考モードONと同じ文章・画質になる保証はありません。無効な応答や途中で切れたJSONは画像生成へ渡さず、書き換えOFFで再試行できるエラーにします。

公式モデルrevision: `f3ed7985c788ad75b3ab7223e0c4c51e2a43545b`。2026年9月21日に公式モデルカードと[Transformersのbitsandbytes資料](https://huggingface.co/docs/transformers/quantization/bitsandbytes)を確認しました。書き換えモデルにも同梱のQwen Research Licenseが適用されます。

2026年9月21日、RTX 3090で249層の4bit化と実モデルの書き換えを確認しました。配布重み18.82GBから、Vision除去とNF4化後の保存重みは6.13GB（約67%減）になりました。日本語入力2件で「雨の日の音楽会」「夏の休憩」をそのまま含む英語説明が返り、後者では赤いマグ1個を左、青いマグ1個を右という指定も保持されました。書き換えだけの所要時間は読み込み等を含め約84秒・44秒、PyTorchが計測したGPU割り当てのピークは約7.0GiB、処理後は8.1MiBです。デスクトップを含むGPU総使用量ではありません。量子化前との文章・画質の比較は未実施です。

### 画像編集の指示補助

**編集指示を書き換える（4bit）**は初期値OFFで、文章用の書き換えとは独立しています。参照画像があるときだけ[公式のQwen-Image-2.1-PE-I2I](https://huggingface.co/Qwen/Qwen-Image-2.1-PE-I2I)に画像と指示を渡し、編集内容を具体化します。参照なしでは使いません。文章用PE-T2Iを編集用に流用することもありません。

```bat
aikimi-qwen-image21-setup.bat --edit-prompt-rewriter-only
```

画像モデルと同時に導入する場合は`--with-edit-prompt-rewriter`、保存ファイルを再検証する場合は`--edit-prompt-rewriter-only --verify`、取得せず導入内容だけを見る場合は`--edit-prompt-rewriter-only --dry-run`を使います。文章用と編集用を両方追加する場合は`--prompt-rewriter-only --edit-prompt-rewriter-only`を指定できます。Neoを終了して導入してください。

編集用は画像認識部をBF16のまま保持し、文章生成部と出力ヘッドを**4bit NF4＋二重量子化**にします。保存先は`models/Qwen-Image-2.1/edit-prompt-rewriter-nf4/`です。文章用と同様に、約19GBの公式元重みを一度取得し、量子化版の保存後の再読込・実際の4bit層・SHA-256を確認してから導入専用の元重みを削除します。完成した4bitモデル、公式指示文、README、LICENSEは保持します。

参照順は`<image1>`、`<image2>`の順に対応します。`Image 1`・`画像1`・`1枚目`のような明示参照も同じ番号として検査します。元の指示に書いた参照番号や、`「文字」`・`"text"`など引用符内の文字が失われた応答、存在しない画像番号、壊れたJSONは採用しません。引用された画像内の文字や、`image 16:9`のような縦横比は参照番号として扱いません。公式指示文が単画像の番号省略を求めるため、参照が1枚だけで元の番号も`ratio_follow`も1のときに限り、本文の`<image1>:`を補います。元の編集指示も最終プロンプトに付記します。これらは機械的な検査であり、意味や人物・背景がすべて保たれる保証ではありません。実際に渡した指示は**使用したプロンプト**で確認できます。

モデルの`wh_ratio`と`ratio_follow`は記録しますが、出力サイズは画面で指定した幅・高さを維持します。思考モードOFF・最大4096トークンで動作し、実行時はローカル保存済みモデルだけを読み込みます。停止とGPU解放は画像生成と共通の管理下にあります。

## INT8とメモリ設定

**W4A8**も選べます。追加ライブラリは `aikimi-qwen-image21-setup.bat --runtime-only` で導入します。精度を選び、**変換モデルを保存**を押すと、画像生成なしでINT8・W4A8を準備できます。「保存済み」と表示されたモデルは、次回から自動で使います。通常の生成時にも自動保存します。対象層、対応GPU、検証結果は [W4A8の使い方](../../docs/w4a8.md) を参照してください。

| 設定 | 動作 |
|---|---|
| INT8 | 生成TransformerとQwen3-VLテキストエンコーダーの対応Linear層をbitsandbytes LLM.int8()で読み込みます。小さな入出力・正規化などの層とVAEは浮動小数点のままです。bitsandbytes内部では入力をFP16へ変換するため、全演算がBF16になる設定ではありません。 |
| BF16 | 公式のBF16構成を読み込みます。INT8より多くのメモリを使います。 |
| CPU退避 | 各部品を使うタイミングでGPUへ転送します。CPU RAMと転送時間を使ってVRAM使用量を抑えます。 |
| GPU常駐 | パイプライン全体をGPUへ置きます。十分なVRAMがある場合に選んでください。 |

INT8は公式BF16重みから変換して保存します。同じ精度・メモリ設定では、読み込み済みモデルを再利用します。上部の**GPU・モデル保持**で、**保持（手動で解放）**・**自動（5分後に解放）**・**毎回解放**を選べます。初期設定は保持です。必要なときは画面上部の共通ボタン**モデルを解放**を押してください。ディスクへ保存したモデルは残り、次回も使用できます。別の生成機能がGPUを使うときや精度・メモリ設定を変えたときは読み直します。

CPU退避では、PNG保存後に未使用のPyTorch GPUキャッシュを解放します。モデル本体の再利用は維持し、GPU常駐ではキャッシュを保持します。`metadata.json`の`memory`に、処理中のピーク、保存後の使用量、解放したキャッシュ量をMiBで記録します。この値はPyTorchのGPU割り当て量であり、パソコン全体のRAMやデスクトップを含むVRAM総使用量とは区別してください。

ブラウザーの描画欄もメモリを使います。Qwenの編集元は短いキャッシュファイル参照で渡し、大きなPNGのBase64文字列を入力欄へ入れる処理を避けています。1024×1280の大きなテスト画像で2回の生成・再編集・ペン入力・PNG/JSON保存を確認し、独立したChromium全プロセスの観測最大RSSは約1,483MiBから約857MiBへ減りました。これはモデルを実行しないUI回帰テストの値です。

上記の実INT8編集では、保存後のPyTorch予約メモリを2,794→88MiB、再実行時は2,716→88MiBへ減らせました。2回の実行で観測したGPU総使用量の最大は15,741MiB（デスクトップ等を含む）、workerのRSS最大は約21.9GiBです。INT8でもCPU退避先のRAMにはモデルが残ります。この検証では上部の**GPU・モデル保持 → 今すぐモデルを解放**でworkerの終了を確認し、PC全体のRAMはピーク約44.9GiBから約22.7GiBへ戻りました。共通設定には**自動（5分後に解放）**もあります。**毎回解放**を選ぶとRAMを保持しない代わりに、次の生成で初回読み込みが再び必要です。

**ここでのINT8はbitsandbytes形式です。Comfy-Org配布のINT8 ConvRotや従来のForge用Qwen単体チェックポイントは、このタブでは読み込めません。** 量子化後の画質・速度・メモリ使用量は設定に依存します。BF16と同じ画像になるとは限りません。

1024角は試作向けの初期設定です。公式の2Kサイズも選べます。大きな画像や多数の参照はVRAMを多く使うため、参照を少なくして試してください。参照画像は公式パイプラインで約1MPを基準に前処理します。マスクは生成後の範囲外固定に使います。モデルへのマスク条件入力、denoise strength、ForgeのLoRA・ControlNet・追加スクリプトはこのタブには接続していません。

## 固定版と検証

- モデル: `Qwen/Qwen-Image-2.1`、revision `b3179ad355be050328e483a9dfdd9e60cd62adfa`
- Diffusers: `6256aa7666cedd47443adc8f82da9a10e110b09c`（Qwen Image 2.1対応の公式コミット）
- Transformers 5.17.0、bitsandbytes 0.50.2、Accelerate 1.15.0
- PyTorch 2.11.0 / CUDA 13.0。対応するNVIDIAドライバーとBF16対応GPUが必要です。
